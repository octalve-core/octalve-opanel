A navigation item, sample data, generated configuration or passing unit test is not proof that the corresponding live hosting feature works. Most technical modules are explicitly unavailable in the production-facing module catalog. The file manager separates example data from actual account inventory. Vendor adapters currently provide read-only foundations, not full vendor management.

## Execution order and acceptance

1. Complete and review durable jobs, lease expiry, idempotency, scheduling and ambiguous-outcome reconciliation.
2. Add authenticated encrypted component backups, scoped PostgreSQL/mail exporters, immutable storage transfer and isolated recovery.
3. Add validated DNS/web activation with readback and rollback; confined runtime configuration and release lifecycle.
4. Add maintained ACME-client orchestration, renewal and verified TLS activation.
5. Connect scoped customer file actions, permissions and bounded staged uploads to the existing interface.
6. Run cross-module and disposable native-service tests, independent review and CI on the exact commit before source merge.
7. Complete the wider database, mail, node/security, accounting and installation gaps listed above; each requires its own implementation and acceptance evidence.

Work can progress with temporary directories, disposable services and CI. Real domain delegation, publicly trusted certificate issuance, actual offsite storage, host isolation/performance and end-to-end delivery still need isolated infrastructure qualification later. Connecting a VPS alone will not complete these gaps. Source merge is separate from deployment and does not authorize Production activation.
